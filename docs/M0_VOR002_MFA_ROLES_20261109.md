## Test methodology

`backend/tests/admin_role_gates.test.ts` imports the **actual production Edge handler modules** with their `Deno.serve` entrypoints intercepted inside an isolated Deno test process. Real `/auth/v1/user`, privileged internal REST/ACL responses and MFA factor lookups are replaced with fixed **synthetic** test fixtures, never network calls. The mock Auth service accepts fixture tokens only, including simulated invalid, expired and revoked responses. This tests the handler's checks of Auth responses, JWT subject/AAL, role permissions, origin and recovery protection; it does **not** verify Supabase's cryptographic JWT signature validation or live refresh-token/session revocation.

Expected automated cases:

1. Anonymous, revoked and expired **simulated Auth responses** → Admin 401.
2. Simulated AAL1 / mismatched JWT `sub` → Admin 403.
3. Missing enabled ACL and unconfirmed synthetic user → Admin 403.
4. Owner, Operator, Auditor → permissioned Admin overview GET.
5. Auditor cannot write; Operator can create **synthetic, in-memory** operational task.
6. Disallowed origin → Admin 403.
7. Vault unauthorized/revoked and AAL1 → 401 / 403.
8. Owner/Operator/Auditor → nonbinary checklist metadata GET.
9. Auditor cannot patch; Operator cannot verify document as Owner.
10. Vault binary upload/download → Owner only; Operator/Auditor denied.
11. MFA recovery → requires verified Owner (anonymous and Operator denied).
12. Verified Owner TOTP → recovery path must **not delete** factor.
13. No synthetic requests access the real Supabase project or write any production data.

CI command: `deno test --allow-env backend/tests/admin_role_gates.test.ts`. Backend source/type checks and existing public Admin/Vault **anonymous 401** live URL health checks continue in CI. No production Auth users or test accounts are created.
